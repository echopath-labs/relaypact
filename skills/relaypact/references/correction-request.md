# Correction request

Use this reference when delivery is incomplete but recoverable within the
agreement. State the exact defect or missing evidence, the currently observed
state, the bounded correction, validations to repeat, what must remain untouched,
and when to stop. Refer to the prior delivery so the executor and Host can
attribute the next result without erasing the first attempt.

Check existing authority before requesting additional paths, context or effects.
Resolve any missing authority before execution; do not silently amend the
original agreement or describe it as previously accepted. A new permission does
not override a selected tool's requirement to start a new task.

## When using a RelayPact CLI lifecycle

Same-session correction is conditional on support in
[invocation.md](invocation.md). Codex correction must retain the task, profile,
capsule baseline, context-manifest identity, prior result and executor thread.
Cursor correction requires persistent state and resumes the protected original
session and bound executable; its one-shot mode has no correction command.

For Codex context changes, including additional readable context, a larger
discovery boundary or a different selected closure, create a new task envelope
instead of expanding the session. Cursor persistent correction also stays within
the original task scope and context. Do not manually rewrite state, identity
bindings or prior results to make a changed agreement look like a continuation.
